# 真实用户场景测试报告

**日期**：2026-10-19
**环境**：opencode zen · deepseek-v4.1-flash · API 引擎 · 全新数据目录
**方式**：全程只在浏览器操作，不使用任何 API 或脚本辅助

---

## 一、任务

模拟一个真实的后台开发需求，完整提给平台：

> 给后台管理页做「批量导出用户数据」功能。运营要按注册时间段导出几万条用户数据为 CSV
> （列：用户ID、邮箱、注册时间、最后登录时间），不能把后端卡死，Excel 打开中文不乱码，
> 且必须记录审计日志。

需求里埋了四个真实约束：**分页/流式**（几万条）、**编码**（Excel 中文）、**PII 审计**、**列定义**。
没有指定技术方案，看猫能不能自己识别出这些点。

| 降级 | 5 次 |

**产物是真的**：沙盒里写出了 `src/export.js`、`src/csv-export.js`、`test/csv-export.test.js`，
共享记忆落了一条决策（366 天 / 5 万条 / 30 分钟 / 重试 2 次的硬性数值）和一条教训
（评审反复打回时先收敛）。

## 三、猫做得好的地方

### 1. 开局就抓到了四个返工风险

宪宪接单后第一次发言就点出：

> 两个会返工的风险先说明：①几万条数据同步查询，会把后端和连接池拖垮，必须限流、熔断；
> ②邮箱属于 PII，权限和审计漏了就要重做。

它没有直接派活，而是先 `list_files` 摸沙盒，再拆。**这是在需求层做判断，不是照单执行。**

### 2. 评审是真的在打回

砚砚四轮 review 全是 `request_changes`，而且每条都带**文件、行号、复现现象、危害、改法**：

> **[blocker] 第 3 条：7 天有效期还是没改** — 现象：本轮输出里「签发时写入 7 天过期时间」
> 仍是绿的 ✔，说明 EXPIRE_MS 还是 7 天，review v3 点名的第 3 条没动。
> 危害：含全量邮箱的下载链接在公网活 7 天，是既定 30 分钟规范的 336 倍。

这不是"看起来还行"式的评审，是真的读了代码、对比了上一轮意见。

### 3. 被拒绝后的降级很体面

我故意让一次审批超时（5 分钟自动拒绝），砚砚没有死循环重试，而是说：

> 补一句给铲屎官：我刚才申请跑 node --test 被拒，所以本轮结论全部基于源码静读 +
> 上一轮真实终端输出（11 绿 1 红）。**我不再重复申请同一命令**；如需我复跑，
> 换个执行方式告诉我，我按新方案走。

### 4. 「批准并记住」确实省事

点一次之后，同一只猫的后续 `run_command` 全都自动放行，没有再打断我。

## 四、发现的问题（按严重程度）

### 🔴 P0：聊天框提需求不会建任务

**现象**：我像真实用户一样，直接在底部输入框粘贴完整需求并回车。四只猫都回应了、
宪宪还发了三张交接卡，但**任务列表是 0，任务进度卡显示"还没有任务"**。

**原因**：`user_message` 只走 `purpose: "chat"`，不会创建任务。

**但界面文案在骗人**：
- 房间副标题写着「把需求丢进来，猫猫们会在同一张桌子上把它做出来」
- 空态提示写着「点上面的「＋ 新任务」，**或在下面直接跟猫猫说需求**」
- 底部提示写着「不 @ 任何人时，宪宪会接住需求」

三处文案都在说"直接说就行"，实际不会开工。**真实用户第一件事就会踩这个坑。**

### 🟠 P1：「卡住了」误报

**现象**：任务显示"卡住了 · 已 18s 没有新动作"，弹出恢复面板让我选继续/换方案/收尾。
但实际上猫正在跑一个模型调用（这次调用本身耗时超过 12 秒的 stall 阈值），20 秒后任务自己恢复了。

**原因**：stall 判定只看 `updatedAt`，没有把"有一次 LLM 调用正在进行"排除掉。

**影响**：真实用户会以为出事了去干预，反而打断正常流程。

### 🟡 P2：消息重复 + 角色名不一致

- 宪宪同一条"燕燕，审计和权限的边界你来划"在聊天区出现了两次（消息 + 交接卡各一次）
- 模型把 `yanyan` 叫成"燕燕"，把 `shuoshuo` 叫成"说说"，而界面显示"砚砚""烁烁"

**原因**：prompt 里给了 catId 但没给"中文名 = catId"的强绑定，模型自己发挥了。

### 🟡 P3：任务结束但没交付

**现象**：任务显示"已完成"，但实际是"被强制收尾"——3 轮修订后评审仍未通过，4 条 blocker 没清。
右侧提示"任务已被强制收尾，可以继续试试或收尾"。

**作为用户我会问**：我现在拿到的东西能用吗？哪些 blocker 还没修？
界面上没有直接答案，得自己翻 14 个产物。

### 🟡 P4：审批卡会被折叠进时间线

任务跑久了会有"↓ 64 条新消息"折叠，审批卡如果在折叠区里就看不见。
好在顶部有 `Needs Me 1` 提醒能跳过去——这是唯一让我发现待办的东西。

## 五、总体判断

**这个平台是真的能干的。**

不是 demo：它写了代码、跑了测试、被打回、被修、最后给出 14 个带版本的产物和一句
"403 已修、bump 到 7 天"这种能直接拿去开会的话。而且 20 分钟里我只点了三次鼠标。

**但它还不是能让陌生用户直接用的产品。** P0 那个问题——"按提示直接说需求，结果不开工"——
会让第一次使用的人以为坏了。

## 六、已修复（本次测试后）

| 问题 | 修法 | 验证 |
|---|---|---|
| P0 聊天框提需求不开工 | 文案改准确；输入框检测到"像需求"的内容时弹引导框，选「开任务」直接把内容预填进任务弹窗 | ✅ 实测：粘贴长需求 → 弹提示 → 点开任务 → 需求已带入 → 任务创建成功 |
| P1 stall 误报 | stall 判定排除"有 LLM 调用正在进行"的情况 | ✅ 单元测试覆盖 |

| P2 角色名不一致 | prompt 里加「房间里的猫」对照表（名字 + catId + 角色），明确要求不要自创/音译 | ✅ 实测新任务，无自创名字 |
| P3 收尾没交代 | 强制收尾时输出「已交付 N 个产物 + 剩余 M 条 blocker + 下一步选项」 | ✅ 单元测试覆盖摘要提取 |
| P4 审批卡被折叠 | 有待审批时底部浮条常驻（红色脉动 + 「🙋 N 项待审批」），优先于"新消息"提示 | ✅ 实测浮条出现并可跳转 |

| P5 房间忙时新需求交叉 | 方案 A：有活跃任务时插入系统提醒「同一个房间一次只做一件事」，输入框上方常驻提示条；用户可点「就是补充给它」显式放行 | ✅ 后端与前端均实测 |
